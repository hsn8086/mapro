# Mapro 下一代地铁图视觉系统规划

## 1. 背景

当前仓库的核心输出是静态地铁图 PNG。现有渲染器已经具备基础能力，但视觉系统仍偏工程实现导向，主要问题包括：

- 站名布局策略较为粗糙，密集区域容易拥挤
- 线路共线时的粗细与间距规则较机械
- 标题、图例与主图未形成统一版式系统
- 状态表达不够清晰，`active`、`planned`、`under_construction` 的视觉层级不足
- 站点徽标、设施标记、换乘连接标签缺乏统一视觉语言
- 渲染层缺少直接测试，视觉调整存在较高回归风险

本规划的目标是建立一套可持续演进的视觉系统，使地图具备更强的专业感、可读性与一致性，同时保证渲染改动可测试、可回归、可分阶段交付。

## 2. 总目标

下一代视觉系统应满足以下目标：

- 更像正式线网图，而不是程序输出的示意图
- 在高密度站区保持可读性
- 配色、线条、站点、标签、图例、标题形成统一语言
- 不同状态的线路和站点有明确区分
- 改动具备足够测试保护，避免修一处坏一片

## 3. 当前问题归纳

### 3.1 视觉问题

1. 标签布局不稳定
2. 多线共线的视觉节奏不自然
3. 版式重心不稳，标题和图例像后贴说明
4. 状态层级表达模糊
5. 细节组件风格不统一

### 3.2 工程问题

1. 样式常量集中度不足，很多参数散落在绘制逻辑中
2. `draw_*` 层几乎无单元测试
3. 缺少小范围视觉回归机制
4. 数据层元信息不足，例如缺少更明确的 `viewport` 策略
5. 某些数据字段会直接影响视觉表现，但缺少校验

## 4. 下一代风格定义

### 4.1 风格定位

下一代风格定位为：

**现代官方线网图风格**

关键词：

- 干净
- 克制
- 准确
- 扁平
- 高可读
- 适度品牌化
- 面向打印和屏幕双端阅读

不是要做成花哨海报，也不是极端极简的抽象艺术图，而是接近“可正式发布”的城市轨道交通线网图。

### 4.2 视觉原则

1. 线优先于字。
线路骨架必须先清晰，标签不能破坏主线路径识别。

2. 信息分级明确。
主标题、线路、站点、站名、辅助说明、状态、设施必须有稳定层级。

3. 同类元素统一。
所有 badge、标签、连接说明、辅助标记应使用同一套圆角、边距、字体等级和颜色策略。

4. 密集区优先可读性。
宁可适当拉开标签，也不要为了贴近站点牺牲可读性。

5. 低饱和底，高辨识主色。
基础文字和版式元素保持中性，让线路色承担品牌识别。

### 4.3 视觉语言

#### 配色

- 背景：纯白或极浅暖灰白
- 主文字：深灰蓝，而不是纯黑
- 副文字：中灰
- 边框和辅助线：低对比冷灰
- 非开通元素：低饱和浅灰，但与 `planned`、`under_construction` 分层
- 线路色：保留数据中的品牌色，但允许做亮度对比修正

#### 线条

- 主线路保持稳定粗细
- 多线共线时优先保证每条线独立识别
- 支线和特殊制式有单独线型规则
- `planned`、`under_construction`、虚拟连接使用差异化线型，而不是只改颜色

#### 站点

- 普通站保持简洁白心圆
- 换乘站有更强识别，但避免过厚描边
- 特殊状态站点要和线路状态一致
- 设施标记不要抢站名视觉层级

#### 文字

- 中文为主，英文为辅
- 中文名负责识别，英文名负责补充
- 英文始终比中文弱一层
- 站名布局应追求方向稳定与局部整洁

#### 图例与标题

- 图例不再是单纯“颜色列表”，而是版式的一部分
- 标题区承担地图名称、版本、更新时间、作者等信息
- 标题和图例位置要与主图整体构图协调

## 5. 圆角与共线设计方向

本节只定义方向，不直接展开到最终实现细节。

### 5.1 圆角策略

当前渲染器只有线段端点的圆头效果，并没有真正的线路转角圆角。下一代方案中，圆角的处理原则如下：

1. 保留现有八方向线路骨架。
2. 在折线拐点引入受控圆角，而不是自由贝塞尔平滑。
3. 圆角半径不能写死，应同时受线宽、相邻线段长度和局部结构约束。
4. 圆角结果必须能被碰撞检测复用，不能只存在于绘制阶段。

风格目标是“小半径、克制、规整”的官方线网图圆角，而不是大曲率、强装饰性的曲线风格。

### 5.2 共线策略

当前渲染器已经具备基础共线偏移能力，但仍属于“可用”而不是“成熟”的方案。下一代共线设计方向如下：

1. 把同一路径上的多条线路视为 bundle，而不是独立线段临时错位。
2. 将“单条线的线宽”和“线与线之间的 gutter”拆开处理。
3. bundle 内部顺序以连续性优先，而不是简单按线路 ID 排序。
4. 分叉与汇合处需要过渡，避免线路突然跳边。
5. 共线几何结果应稳定复用到绘制、碰撞检测和标签避让逻辑。

### 5.3 两者之间的关系

圆角和共线不能拆开孤立修补。

- 只做圆角，不做共线稳定化，会导致多线拐点松散
- 只做共线，不做圆角，转折处仍会显得机械
- 正确顺序应是：先确定中心线与 bundle 规则，再处理偏移路径，最后处理圆角与绘制

## 6. 实施范围

本次规划分为四个层面：

1. 样式系统层
2. 标签与线路几何层
3. 版式布局层
4. 测试与回归保障层

## 7. 分阶段实施策略

### 阶段一：建立样式系统基座

目标：

- 把零散硬编码收束到样式常量中
- 明确颜色、字号、线宽、圆角、边距、状态风格规则

涉及模块：

- `map_gen/styles.py`
- `map_gen/draw/stations.py`
- `map_gen/draw/lines.py`
- `map_gen/draw/legend.py`
- `map_gen/draw/links.py`

交付结果：

- 可配置的样式常量表
- 状态视觉规则初版
- badge 与标签基础规格统一

### 阶段二：优化站名与徽标排布

目标：

- 减少站名碰撞与杂乱感
- 建立更稳定的标签评分机制

涉及模块：

- `map_gen/draw/stations.py`

核心动作：

- 将 first-fit 搜索升级为候选位置评分
- 统一 marker、facility、文本块的排布规则
- 为极端密集区域预留引导线策略

交付结果：

- 标签排布更稳定
- 局部区域读图体验显著提升

### 阶段三：优化线路几何与状态表达

目标：

- 改善共线线路的视觉品质
- 建立 `active`、`planned`、`under_construction`、`inactive` 的稳定样式体系

涉及模块：

- `map_gen/draw/lines.py`
- `map_gen/draw/links.py`
- 必要时补 `map_gen/segments.py`
- 必要时补 `map_gen/router.py`

交付结果：

- 多线路共线更自然
- 状态表达更清晰
- 换乘连接更容易理解

### 阶段四：标题、图例与主图形成统一版式

目标：

- 让标题和图例从“后贴说明”变成布局系统的一部分

涉及模块：

- `map_gen/renderer.py`
- `map_gen/layout.py`
- `map_gen/draw/title.py`
- `map_gen/draw/legend.py`

交付结果：

- 页面重心稳定
- 留白更合理
- 成图整体更像正式作品

## 8. 防回归策略

### 8.1 核心原则

任何视觉改动都必须遵循：

1. 先加保护，再做调整
2. 小步提交，不做大爆改
3. 每阶段都能独立验证
4. 视觉变化必须可解释，不接受“看起来差不多”

### 8.2 为什么修一处会影响下一处

渲染系统天然是联动的：

- 标签偏移变了，可能压到图例
- 线宽变了，站点半径和标签避让阈值也要跟着变
- 状态颜色变了，badge 和图例也要一起改
- layout padding 变了，标题、图例和地图本体位置都可能漂移

因此不能把每个模块当成完全独立的 UI 组件，而要把它看成一个共享坐标系和共享样式系统。

### 8.3 控制风险的方法

1. 建立 `draw_*` 层单元测试。
需要补充以下测试：

- 标签碰撞检测测试
- 标签避让策略测试
- 多线共线 offset 测试
- 状态线型与颜色测试
- 图例尺寸与布局测试
- 标题块高度计算测试
- 换乘连接标签锚点测试

2. 引入小范围视觉快照测试。
不是全图死比对，而是对稳定小样本做局部像素回归：

- 单线段
- 双线共线段
- 普通站与换乘站
- 标签密集区域
- 图例块
- 标题块

3. 分阶段推进。
每次只动一类问题：

- 先样式常量
- 再标签
- 再线路
- 再版式

4. 保留旧行为的参考输出。
在改动期间保留一组参考渲染结果，用于人工比对。

5. 数据问题单独治理。
数据错误不能混在渲染器视觉重构里一起改，要单独列出并单独验证。

## 9. 测试策略

### 9.1 单元测试

建议新增测试文件：

- `tests/test_styles.py`
- `tests/test_draw_lines.py`
- `tests/test_draw_stations.py`
- `tests/test_draw_legend.py`
- `tests/test_draw_title.py`
- `tests/test_draw_links.py`

### 9.2 集成测试

保留并扩展渲染流程测试，覆盖：

- 目录地图包渲染
- 含 `viewport` 的渲染
- 含 `connection` 的渲染
- 含 `planned`、`inactive`、`under_construction` 的渲染

### 9.3 视觉回归测试

建议建立稳定样本集：

- 极简样本图
- 双线共线样本图
- 高密度站名样本图
- 带图例和标题的完整样本图

目标不是追求像素完全一致，而是确保结构性变化符合预期。

## 10. 数据协同策略

视觉优化不只依赖渲染器，还依赖数据质量。

建议同步推进以下数据规范：

1. 校验线路 `type` 的枚举值
2. 校验 `service` 等会影响 marker 的字段合法性
3. 评估是否为 APM 等系统引入独立类型
4. 为重要地图补充 `meta.viewport`
5. 梳理“同名双站 + connection”是否需要更强的视觉表达或数据模型调整

## 11. 成功标准

当满足以下条件时，认为下一代风格第一阶段成功：

1. 站名密集区域可读性明显提升
2. 共线线路更容易区分
3. 标题与图例和主图更协调
4. 状态表达清晰
5. badge、设施、连接标签风格统一
6. `draw_*` 层有直接测试保护
7. 生成结果在示例地图上稳定，不出现明显布局倒退

## 12. 暂不处理的事项

以下内容不纳入本轮视觉系统重构：

- Web 前端交互式渲染
- 地图编辑器
- 动画效果
- 多主题动态切换
- 三维或拟物质感表现

当前聚焦于 Python 静态渲染质量提升。

## 13. 下一步执行建议

建议按以下顺序进入实现：

1. 先补 `draw_*` 层测试骨架
2. 再整理样式常量和状态规范
3. 接着重做站名布局
4. 再处理线路共线与状态线型
5. 最后做标题图例版式升级

这样可以把“改一处坏另一处”的风险压到最低。
